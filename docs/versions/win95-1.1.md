# Windows 95 1.1 (May 1996)

Previous: [Win95 1.0](README.md#win95-10-february-1996). Next: [Win95 1.2](win95-1.2.md).

## Behavioral changes: 1.0 → 1.1

`-` is 1.0; `+` is 1.1. These are compact source-level illustrations of the
reviewed retail changes, with surrounding code omitted. Compiler-only register
and comparison changes are listed in the [changed-function table](#changed-functions).

### Chat moves from F1 to F2

Combat chat and chat while waiting for a network player use F2.
Applies to `combatManager::Main`, `ProcessCombatMsg`, and
`advManager::CheckHandleNetPlayerWait`.

```diff
-case INPUT_SCAN_F1:
+case INPUT_SCAN_F2:
     PopNetBox(NULL);
```

### Castle hover recognizes secondary triggers

`advManager::ProcessHover` accepts either trigger on each of the two cells
above and below the target. Here `adjacent` abbreviates either neighboring cell;
both cells must still satisfy the town test.

```diff
-(adjacent->m_triggerType & MAP_TRIGGER_TYPE_MASK) == MAP_OBJECT_TOWN
+((adjacent->m_triggerType & MAP_TRIGGER_TYPE_MASK) == MAP_OBJECT_TOWN
+ || (adjacent->m_secondaryTrigger & MAP_TRIGGER_TYPE_MASK) == MAP_OBJECT_TOWN)
```

### Hover refreshes after remote loading and at a local human turn

`LoadRemote` refreshes unconditionally at its end. `NextPlayer` refreshes when
the new player is a human controlled by this machine.

```diff
 // advManager::LoadRemote
+gpAdvManager->ForceNewHover();

 // game::NextPlayer
+if (gbThisNetHumanPlayer[giCurPlayer])
+    gpAdvManager->ForceNewHover();
```

### Identify Hero expires on player change

The flag is cleared on each player transition rather than only at the daily
update.

```diff
 // game::PerDay
-gpAdvManager->m_identifyHeroActive = 0;

 // game::NextPlayer
+gpAdvManager->m_identifyHeroActive = 0;
```

### Restored setup fills unset human handicaps

Inside `game::NewGame`'s saved-settings guard, later human players with
`HUMAN_HANDICAP_NONE` inherit the first player's handicap. This does not run
when there are no saved setup settings.

```diff
 if (gNewGameSettingsSaved) {
     // Restore saved settings.
+    for (player = 1; giNumHumanPlayers > player; player++) {
+        if (m_players[player].m_difficulty == HUMAN_HANDICAP_NONE)
+            m_players[player].m_difficulty = m_players[0].m_difficulty;
+    }
 }
```

### Erasing an object also clears its animation flag

`advManager::EraseObj` removes the animation state alongside the object frame.

```diff
 cell->m_objectIndex = MAP_CELL_NO_FRAME;
+if (cell->m_flags & MAP_CELL_OBJECT_ANIMATED)
+    cell->m_flags -= MAP_CELL_OBJECT_ANIMATED;
```

### Combat clears queued input and resets the mouse later

`combatManager::Open` moves `ResetMouse` after music setup and adds an input
flush immediately before it. Intervening setup is omitted here.

```diff
-ResetMouse();
 // Select the battle music.
 gpSoundManager->SwitchAmbientMusic(song);
+gpInputManager->Flush();
+ResetMouse();
```

### Serial failures produce a diagnostic and shut down

`com_init`, `com_rcv`, `com_snd`, and `comm_wrt_task` check failures from port
creation/configuration, error-queue clearing, reads, writes, and break control.
The added `ShutdownComError` names the Windows error, adds troubleshooting
suggestions, and invokes the existing shutdown path. Example from `com_rcv`:

```diff
-ReadFile(gComPorts[port].handle, buffer, currentBytesRead, &nRead, NULL);
+ioResult = ReadFile(gComPorts[port].handle, buffer, currentBytesRead, &nRead, NULL);
+if (!ioResult)
+    ShutdownComError("Read communications data");
```

### CD stopping waits for completion

`CDStop` adds the MCI `wait` modifier. The separate `CDShutdown` command stays
`stop CD`.

```diff
-wsprintfA(CommandString, "stop CD");
+wsprintfA(CommandString, "stop CD wait");
```

### Ultimate-artifact rolls consume RNG state in a different order

At both spread calculations in `game::NewMap`, retail changes the roll ranges
from **20, 20, 30** to **30, 20, 20**. The sum's distribution is unchanged, but
the same initial RNG state can produce a different spread and artifact location.

```diff
-ultimateSpread = Random(1, 20) + Random(1, 20) + Random(1, 30);
+ultimateSpread = Random(1, 30);
+ultimateSpread += Random(1, 20) + Random(1, 20);
```

### AI floating-point accumulation order changes

The terms and weights stay the same; rounding can differ. In `RVConversion`,
each abbreviated resource name below means its quantity multiplied by its AI
resource weight:

```diff
-gold + gems + mercury + ore + sulfur + crystal + wood
+ore + gems + mercury + gold + wood + sulfur + crystal
```

`ValueOfEventAtPosition` changes artifact weighting and the final two terms of
the campfire resource sum:

```diff
-gPrizeUnguardedValue * 0.6 + gItemPurchaseScore * 0.2 + gPrizeGuardedWorth * 0.2
+gPrizeUnguardedValue * 0.6 + gPrizeGuardedWorth * 0.2 + gItemPurchaseScore * 0.2

 // Campfire: preceding terms and subsequent scaling are unchanged.
-... + gafAITurnCostResource[RESOURCE_CRYSTAL] + gafAITurnCostResource[RESOURCE_WOOD]
+... + gafAITurnCostResource[RESOURCE_WOOD] + gafAITurnCostResource[RESOURCE_CRYSTAL]
```


### Version text and assertion metadata

The loading message and About dialog say 1.1 (the About text is resource data:
type 5, name `HEROES`, language 1033, one UTF-16 digit at payload offset 198;
no other resource changes). `GiveExperience`'s `/Gi` line static changes from
1110 to 1113; its assertion offsets remain +8 and +9. Experience logic does
not change.

```diff
-Loading Heroes of Might and Magic for Windows 95 (version 1.0)
+Loading Heroes of Might and Magic for Windows 95 (version 1.1)
-Version 1.0
+Version 1.1

 // GiveExperience diagnostic line static
-1110
+1113
```

## Build

NWC's May 7, 1996 Windows 95 1.1 `HEROES.EXE` (editor of May 6) is
reconstructed on `decomp-win95-1.1`, branched from `decomp-win95-1.0` at
`f323b279`. The compiler is still VC4.0 with per-unit `/Zi /Gi` profiles and
`D:\Heroes` source paths. Runtime libraries remain WAIL32, SMKWAI32 and WING32.

## Address correspondence

[`win95-1.0-to-1.1.tsv`](../../config/retail/versions/win95-1.0-to-1.1.tsv) records the old and new RVAs of inherited
claims. The correspondence used normalized byte fingerprints, checked monotonic
link order, paired call targets, and vtable slots. Changed bodies were aligned
between anchors; conflicting operand pairs were checked against neighboring
references rather than resolved by voting. Data interiors were translated only
where the surrounding mapped references had the same displacement. 
The added function at RVA `0x072e57` is `ShutdownComError`, in
`SOURCE/comwin.cpp`. It sits between `init_anchor` and
`com_init`. It is not part of the preceding function's contribution.

For another comparison, the read-only discovery command is:

```sh
homm1 sema fid --old /path/to/old.exe --new /path/to/new.exe \
  --census /path/to/old/config/retail/functions.tsv --out build/fid.json
```

The census must describe the **old** image. Each result includes a fingerprint,
candidates, and its order bracket. Only relocation fields and decoded relative
branch operands are masked; a non-address immediate remains significant.
Fingerprints are candidate identities, not strict-match evidence. Referents and
branch destinations still require inspection. Nonmonotonic unique anchors stop
the command. No source or census is automatically rewritten.

## Changed functions

The review compares the February 1.0 executable with May 1.1. The complete
per-census-entry inventory, including unchanged and address-translated
entries, is [win95-1.0-to-1.1-review.tsv](../../config/retail/versions/win95-1.0-to-1.1-review.tsv).

The first byte-fingerprint pass is only discovery: HIGHLOW operands, relative
branches, inline jump tables, alignment, and compiler-generated EH continuations
must be checked separately. Comparing the modeled retail objects and their
ordered references adds cases that address masking alone hides. In particular,
an unchanged instruction can load the other side of a comparison, a different
term of a floating sum, or a changed string. The comparison found 51 inherited
functions to review, in addition to `ShutdownComError`.

The original census has inherited runtime entry omissions. Independent call,
pointer, prologue, and padding scans found no additional new game function.
That supports this review's scope; it is not a proof of an exhaustive census or
of all possible changes to unreferenced data. This report also does not claim
runtime play testing.
