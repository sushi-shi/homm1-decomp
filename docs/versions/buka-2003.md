# Buka 2003 (Russian Platinum edition)

Previous: [Win95 1.2](win95-1.2.md).

`decomp-buka-2003` reconstructs the Russian Buka 2003 `HEROES.EXE` pinned in
[`config/retail/targets.json`](../../config/retail/targets.json). It branched
from `decomp-win95-1.2` at `43cf275fee2f181375d208f58b101536bc34fc7c`. The
compiler is VC6 SP5 and the matching locale is Russian; an English catalog
builds the same code in English. Match status is the generated block in the
[README](../../README.md).

This page records what Buka changed relative to the NWC Win95 1.2 build and
the retail quirks the reconstruction keeps. Input hashes and PE inventories of
both releases are in [`versions/images.json`](../../config/retail/versions/images.json);
the 1.2-to-Buka address correspondence is
[`versions/win95-1.2-to-buka-2003.tsv`](../../config/retail/versions/win95-1.2-to-buka-2003.tsv).
RVAs are relative to the image base `0x400000`; source `VA(...)` annotations
are absolute.

## Executable and toolchain

| Area | NWC 1.2 | Buka 2003 |
| --- | --- | --- |
| Compiler | VC4.1, incremental `/Gi` | VC6 SP5, mostly `/Od`; FINDPATH/SEARCH use `/O2 /Ob2 /G5`; assertion lines are immediates |
| Link | Base relocations, `/OPT:REF` | `/FIXED`, `/OPT:NOREF` |
| Imports | Separate `.idata` | Import directory in `.rdata` |
| Text | English | Russian, Windows-1251 bytes |
| Audio | CD MCI and Miles digital music | Audiere playback; Ogg music |
| Smacker | Named imports | Nine ordinal imports from the shipped Watcom-built DLL |
| Registry | NWC installation key | `SOFTWARE\Buka\3DO\Heroes of Might and Magic Platinum\1.000` |
| Resources | Language 1033, icon group `HEROES` | Language 1049, icon group 109 |

Per-unit compiler profiles are in [`config/units.toml`](../../config/units.toml).
Units use `/Od /Ob1 /GX /MT` with `/G5` or `/G6` chosen by whole-unit controls:
`/G6` adds narrow-argument register clears that some units lack. REQUEST uses
`/Od /Ob2 /G5`, which emits file-scope initializer literals in source order
([`vc6-ob2-literal-order.md`](../patterns/vc6-ob2-literal-order.md)).

Link layout facts:

- Every retail C++ object ends with the `ctype<wchar_t>::id`
  initializer/registration pair that `<string>` emits (62 pairs, matching the
  Rich header's 62 C++ objects). The project prelude opens `<string>`. The
  one-byte COMMON guard is at `0xd82d8`
  ([VC6 locale startup](../patterns/vc6-ctype-startup.md)).
- Retail keeps the unreferenced `??_H` COMDAT (`0x1c900`) and a thunk for
  every import slot. The first thunk run (WINMM..NETAPI32,
  `0x685e0..0x688b6`) separates the SOURCE objects from the BASE library,
  which starts at BASEMGR (`0x688c0`).
- The Audiere sample, music and device code is one translation unit,
  [`Audio.cpp`](../../src/BASE/Audio.cpp). VC6 aligns each object's `.text` to
  16 bytes; the two odd, unfilled boundaries inside this band (`0x69126`,
  `0x69a8e`), its single `ctype` pair after the device code (`0x69df2`) and
  its adjacent static-destructor guards (`0xcdf70`, `0xcdf71`) show one
  object. Merging the sources gives retail's 66 `.CRT$XCU` entries and BASE
  pull order (BASEMGR, Audio, WINMGR). The merged object still orders the
  two guard bytes opposite to retail.
- Out-of-line destructors (`~icon`, `~iconWidget`, `~bitmap`, `~palette`,
  `~border`, `~tileset`, `~textEntryWidget`, `~button`) sit between their
  neighbours in source order, so retail defined them out of line;
  `~backdropWidget` and `~dimmerWidget` follow their objects' `??_G` helpers
  and stay `inline`.
- ADVMGR's `.rdata` has 12 zero bytes between `gEnvironmentVolume` and
  advManager's vtable: the table has eight slots, five initialized.
- Retail was linked `/DEBUG`: `.rdata` holds the IAT (`0x348` bytes), then a
  `0x1c`-byte CodeView debug directory at `0x48a350`, and the image ends with
  a 73-byte NB10 record for
  `E:\Users\igorl\VSS\HMM\HMM1\temp\release\game\heroes.pdb`
  (signature `0x3e5cda55`, age 2). The candidate links `/DEBUG` with that
  `/PDB` path on a Wine drive E: (`build/pdb-drive`).
- The NB10 signature is the time LINK created the PDB (`0x3e5cda55`,
  2003-02-26 15:16:37 UTC) and its age counts the links that wrote it; the
  header and debug-directory timestamps are the final link (`0x3e96d447`,
  2003-04-11 14:42:15 UTC). `homm1 link` reads these from the retail image
  and repeats the history under libfaketime (`HOMM1_FAKETIME_LIB`): one link
  at the PDB time against a fresh PDB, one at the link time.
- Initialized `.data` matches retail object by object:
  - PlayMusic's `"\TRACKS\"` operand is KB's 352-byte path global
    `gTracksPath` (between `gSoundPath` and `gGamePath`); KB's
    `gGameTypeHelp` sits at `0x492f3c` with the Russian texts.
  - EXEC's manager-list texts and INPUTMGR's `ReleaseCapture` failure texts
    are absent from the image. MOUSEMGR's cursor formats and `CO`/`BW`
    suffixes are SetPointer literals (suffix pushed before format, three
    times).
  - CMBTMGR and kbwin are compiled `/Ob2`: CMBTMGR's static
    `gCombatBkgNames` follows `gSeed` with its strings among the function
    literals, and kbwin's `gcCDTrackName` literal sits between the
    preference and CD-probe literals
    ([VC6 `/Ob2` literal order](../patterns/vc6-ob2-literal-order.md)).
  - LZHUF's tables are `d_code`, `d_len`, `initialSon`, `initialParent`,
    `initialFrequency`.
  - Values no retail code reads, kept for their place: an `i32` 28 after
    ADVMGR's `gLastHourGlassPhase`; two sixteen-entry byte tables after KB's
    `gSpellCastNumMod` (also in the Win95 1.0 image); an `i32` -1 in kbwin;
    REMOTE's three `i32` -1 and its baud-rate and IRQ choice tables; four
    zero bytes in Icon2b and twelve in BMAP2.
  The remaining `.data` differences are pointers into `.bss`.

### Import libraries and the library line

The Rich header counts the objects each tool produced:

| prodid (build) | retail | VC6 libraries only | reading |
| --- | --- | --- | --- |
| 1 Import0 | 179 | 194 | short import members |
| 0 unmarked | 30 | 9 | long import members and pre-VC5 descriptors |
| 0x13 LINK 5.12 (8034) | 11 | 13 | VC6 Platform SDK descriptor objects |
| 4 LINK 6.00 (8447) | 2 | 6 | audiere.lib's descriptor pair |

The six ML 6.11 objects carry no `@comp.id`. Of the 200 imports, 21 are long
members: WING32's six and 15 from mss32 (5), smackw32 (9) and NETAPI32 (1),
which are LINK 3.10 long-format libraries
([`import_libraries.tsv`](../../config/retail/import_libraries.tsv)). Retail's
`Netbios` hint is 180, as in the VC4.1 `netapi32.lib` (VC6's records 211),
and with these libraries every IAT slot outside the CRT's KERNEL32 group and
every `.idata$6` hint equal retail's. Buka therefore linked the 1996
vendor and network libraries, not regenerated ones.

- `OLDNAMES.LIB` precedes `winmm.lib`: its alias members have an empty,
  16-byte-aligned `.text`, and the six old names SOURCE calls (`open`, `read`,
  `close`, `write`, `strcmpi`, `strnicmp`) are pulled before WINMM's thunks,
  so the first thunk follows seven `CC` bytes at `0x4685e0`.
- `audiere.lib` precedes the BASE library. Its imports are referenced only
  by `Audio`, so they resolve in LINK's second pass, after the CRT's
  KERNEL32 and BASE's USER32/GDI32 imports, as retail's thunks
  (`0x48871e`) and hint/name strings show.
- kbwin keeps `_chdir`/`_lseek`: as aliases, `chdir.obj`/`lseek.obj` would
  move from after `strncpy.obj` (retail) to after `stricmp.obj`.
- Retail's Rich header counts 10 OLDNAMES alias objects. The only alias
  members whose loading moves no CRT object are `lseek` (from RESMGR, which
  spells its file calls `open`/`read`/`lseek`/`close`/`tell`) and `stricmp`
  besides `strcmpi`; GAME's `REMOTE.GAM` test uses `stricmp`. The count
  proves a second spelling of that runtime body; which call site used it
  leaves no other trace.
- `msvcprt.lib` follows the BASE library: retail's `operator delete` is its
  `delop_s.obj`. LINK orders Rich entries by each tool's last object in a
  walk over the libraries in reverse search order (each in load order), then
  the command-line objects; with `delop_s.obj` in its own library the C++
  runtime entry follows the C and MASM ones, as in retail.
- Audio's sample-list node is the class template `AudiereNode<sample>` with a
  declared destructor: only that shape emits the destructor after the
  `RefPtr` members, as at `0x469f80`
  ([VC6 COMDAT order](../patterns/vc6-comdat-emission-order.md)).
- Retail `.bss` holds objects no code reads (also present in the Win95
  1.0-1.2 images); each is declared at its place, either as an uninitialized
  object whose name's key lands in its window or as a zero-initialized one in
  definition order ([VC6 `.bss` order](../patterns/vc6-bss-emission-order.md)).
  VC6 aligns every record-typed object of 8 bytes or more to 8, so REMOTE's
  `rcvBufIn` at `0x4cb664` is a byte buffer.

The linked candidate is byte-identical to the retail image;
`homm1 verify link-diff` (in `homm1 build verify`) keeps it so.

The LZHUF decoder was not recompiled with VC6; it is the pre-built NWC module
(see [`vendor/lzhuf/README.md`](../../vendor/lzhuf/README.md)). The encoder
defines its functions in retail order, with its `static` helpers after their
callers so VC6 emits them in place
([static deferral](../patterns/vc6-static-function-deferral.md)).

## Localization

Russian text lives only in [`locales/ru.po`](../../locales/ru.po), and
[`locales/en.po`](../../locales/en.po) translates the same IDs into English
([localization](../localization.md)).
Authored C++ and RC contain catalog IDs, not Russian literals or numeric text
escapes. Every migrated pointer slot and literal is checked against both
executables ([`localization.tsv`](../../config/retail/localization.tsv)).
`homm1 verify localization` checks coverage, printf signatures, fixed-width
lengths and strict code page encoding for every language. Buka's ЙЦУКЕН key
table (`0x4A1388`) is the Russian descriptor's keyboard.

Behavioural consequences of the translation:

- **Case conversion.** First-letter capitalization uses `CyrillicToUpper`
  (CP1251-aware, including the separate Yo pair) instead of subtracting 32;
  names copied into sentences use `CyrillicToLower`. `toupper` uses the same
  helper. Affected: `CheckEndGame`, `ReceiveRemotePlayerExit`, `ShowCongrats`,
  `highScoreManager::Update`, `SetupWell`, hot-seat and new-turn prompts,
  resource pickups, town command text, combat messages and network-combat
  notifications.
- **Plural names.** Recruitment, creature-week/month announcements, town
  selection/movement/exchange/dwelling prompts, attack and shooting commands
  and luck messages use `gArmyNamesPlural`. `GetMonsterName` (`0x3e3cf`) reads
  the plural table; the adjacent singular accessor (`0x3e3c0`) reads
  `gArmyNames`. The shooting command drops the English conditional `"s"`
  argument. Combat kill messages lowercase a singular victim's name in a
  100-byte shared buffer and use the plural for more than one.
- **Damage messages** add an attack prefix argument and always take the
  attacker's plural name; hydra attacks use generic troop fragments. The
  genie translation omits "half"; the damage arithmetic is unchanged.
- **Sprite names.** Creature graphics use a separate, locale-independent
  table, `gArmySpriteNames`, whose 28 stems equal the original English names
  (the `swrdsman` exception is unchanged).
- **Mine names.** Quick info uses a seven-entry table of complete mine names
  (`0x92804`) instead of appending "Mine" to a resource name.
- **Campaign town names** occupy exactly 16 characters, including padding
  spaces and without a terminator, inside the packed scenario records (table
  at `0x91ce0`).
- **Fonts.** Text drawing, wrapping, line counting and width measurement
  widen bytes without sign extension and map CP1251 letters to extra font
  frames through `RemapCyrillicCharacter`. Bounded drawing
  inserts temporary line terminators into a private copy; line counting no
  longer writes into the caller's text.
- **Keyboard.** Character key codes go through the CP1251 keyboard table
  unless a Control modifier is held.
- **Filenames.** `GenerateStandardFileName` and `fileRequester::Main` accept
  CP1251 letters of both cases, including Yo; byte comparisons are unsigned.
- **Resources.** All 164 menu/dialog labels use the catalog; the build
  expands them into wide literals in a temporary RC view (narrow CP1251
  escapes produce Latin-1 code points with RC.EXE). The About dialog still
  names icon `HEROES` although the group is 109, as in retail.
- **Single instance.** The named startup event changes from `Heroes` to
  `Герои`, an executable behaviour change rather than a dialog translation.
- `gLuckInfoText` has eleven entries (the NWC null slot is gone); each combat
  terrain table has seven filenames.

## Audio and video

Audiere replaces the CD MCI/Miles sound manager:

- Music plays `%sHeroes%02d.ogg` or `%s%s%02d-AudioTrack %02d.ogg` through a
  100-entry 32-bit CD-track map (track 99 maps to disc track 50) with 100
  saved-position slots. `SetMusicSource` (`0x698fb`) stops and releases the
  stream, clears every saved position and restarts the previous track from
  the beginning; playing the selected track resumes a stopped stream. Music
  source is a boolean (`SOUND_MUSIC_SOURCE_CD = 1`); the control panel still
  shows display entries 0 and 2.
- Suspension is a nesting counter per channel; play, stop and volume refresh
  return while it is positive. Combat and AI suspend and restore channels and
  the saved track.
- `sample::sample` (`0x75050`) takes only a filename, sets full volume and a
  false repeat flag, defaults to 44100 Hz / 16-bit / stereo, allocates with
  `new` and adds `0x80` to every loaded byte, including 16-bit data. The
  sample record is `0x2a` bytes. Audiere treats the repeat flag as
  `flag != 0`. Per-sample volume is scaled by `127.0f`.
- Army, movement and cursor sample volumes are 127 instead of 64. Ambient
  distance volumes are `{127, 96, 63, 31, 21}` instead of
  `{64, 48, 32, 16, 10}`, and the ambient update no longer waits for a
  sound-manager readiness flag.
- `WaitSample` polls with `DelayMilli(10)` and frees the stream node, not the
  sample resource.
- The adventure screen restores both volume channels on `Open` and calls
  `StopAllAudio` on `Close`; `combatManager::FreeArmies` and scenario entry
  stop all audio, including music.
- Changing walk speed or closing the adventure screen skips null cursor
  samples (and clears each slot after disposing it).
- **Quirk:** `InitAudio` (`0x69bd5`) first opens `winmm`; if that fails but
  the `null` device opens, it releases that device and still returns true.
  Audiere's fallback identifier is `"null"`.

Smacker playback has
its own loop with six 27-byte movie-option rows and returns whether a movie
completed. The introduction plays `SMACK_BUKA`, then `SMACK_NWCLOGO`, then
`SMACK_INTRO`, each only if the previous one completed, unless intros are
skipped. Before playback Buka stops music, closes Audiere, selects the first
supported of twelve WinMM formats and opens a temporary Miles driver;
afterwards it reinitializes Audiere and restores both palettes and the
cursor. Movie volume follows the effects volume. Playback hides the pointer
with `ReallyHidePointer`/`ReallyShowPointer`. The winning-movie caption
starts at frame 22 at (32, 342) in a 320 by 106 rectangle, color 4.

## Configuration, registry and startup

- `ReadPrefs` (`0x43f8f`) and `WritePrefs` contain the registry operations
  directly. Reading creates the key (`RegCreateKeyA`); writing opens it with
  `KEY_ALL_ACCESS`. Values are renamed with an `HMM1` prefix (`HMM1
  MusicVolume`, `HMM1 FXVolume`, `HMM1 CDDrive`, window and network settings).
  A successful read applies `SetVolumes` and `SetMusicSource`.
- The configuration drops `cdOffset` and `slowVideo`: the struct shrinks from
  `0x134` to `0x12c` bytes, music source moves from `0xb8` to `0xb4` and the
  modem settings move four bytes earlier. Walk speed defaults to Canter on
  every CPU. The AI always takes the former normal-video path: no doubled
  step limit, difficulty factor `0.06`, and search range 36 for non-immediate
  strategic evaluation.
- `InterpretCommandLine` clears `gbNoSound` after parsing, overriding the
  legacy `/S` option.
- Animation and sound paths are relative (`.\ANIM\`, `.\SOUND\`).
- `AppInit` loads icon resource 109. `AppIdle` returns true directly.
  `EarlySetup` dispatches CD errors through a switch.

### Disc discovery

The CD check (`0x44774`) looks for `Tracks\02-AudioTrack 02.ogg` instead of
`_autorun\autorun.exe`. It first validates local `DATA\HEROES.AGG` (changing
to the registered install directory if needed). A registered drive is accepted
when its letter is valid, `GetDiskFreeSpaceExA` succeeds with critical-error
dialogs suppressed and the track opens. Otherwise each CD-ROM drive is tried
twice, reading the track's final 100 bytes, and the drive is recorded as
`HMM1 CDDrive`; each unsuccessful pass sleeps three seconds. The MCI commands
and sound/animation path rewriting are gone. Retail quirks: only 26 bytes of
the 26 integer drive slots are cleared, the probe path is drive-relative, a
short read is accepted unless it returns -1, and a registry-open failure does
not invalidate a successful probe.

## Compression and network transfer

The LZHUF codec keeps its window, adaptive Huffman rules, four-byte
big-endian length header and tables. Buka drops the
decoded-data log call and calls the final-byte flush as a separate function
(`EncodeEnd`, `0x7474c`). The decoder is the pre-built NWC module, byte-equal
after masking absolute addresses except for a word-immediate `cmp` in
`DecodePosition`. Runtime properties, including the save-transfer
truncation, are in [`vendor/lzhuf/README.md`](../../vendor/lzhuf/README.md); a
Rust port is in [`tools/`](../../tools/README.md).

## Game data and retail runtime baseline

The [Buka Platinum disc](https://archive.org/details/***REMOVED***)
contains the exact executable. The downloaded RAR matches the archive's
SHA-1 `95051a705656438c474fe649ecf95fa96f463d6a`. Extracting its ISO with `7z`
and `autorun/launch/Setup1/data1.cab` with `unshield` supplies the AGG, maps,
cinematics and 49 local Ogg files; the disc also supplies 49 `Tracks/` Ogg
files. The 161 asset/executable hashes are in
[`assets.json`](../../config/retail/assets.json); the files stay under
ignored `build/preflight/`.

The unmodified executable reaches the Russian main menu under Wine with these
assets and its shipped DLLs, using a separate prefix, a CD-ROM drive mapped to
the extracted disc and the 32-bit Buka registry values. Wine must restart
after the drive mapping is established.
