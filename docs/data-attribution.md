# Data attribution

The current campaign matches code first. Admit identities and layouts required
by code; defer initializer coverage and data placement until the later phase.
An owner-header extern is usable evidence debt, not a recovered definition.

`DATA(va)` from `include/match.h` records identity; it does not force linker
placement. Never split an interior address into overlapping storage or add
padding arrays to improve a score. Literal pooling, header-static copies and
COMMONs require evidence of every emitter and the correct ownership model.

The existing data manifest builder emits derived manifests under `build/gen`.
The normalizer writes disposable pairs while raw candidate/target objects stay
available. Data-identity auditing checks contradictions across matched reference
layouts in both comparison modes. Aggregate data percentages are not coverage.

The explicit `homm1 verify check --tier data` holds placement, relocation,
access, coverage and vtable audits for the data campaign. Consult the actual
modules for their schemas and prerequisites; Giten's data ledgers and extra
annotation macros are not HoMM1 claims.
