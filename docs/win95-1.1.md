# Windows 95 1.1 fork

This repository branches from `sushi-shi/homm1-decomp` master at
`f323b279` and targets NWC's May 7, 1996 Windows 95 1.1 executable.
The game and May 6 editor hashes are pinned in `config/retail/targets.json`.
The compiler remains VC4.0 with the inherited per-unit `/Zi /Gi` profiles and
`D:\Heroes` source paths. Runtime libraries remain WAIL32, SMKWAI32 and WING32.

## Address correspondence

`config/retail/win95-1.0-to-1.1.tsv` records the old and new RVAs of inherited
claims. The migration used normalized byte fingerprints, checked monotonic
link order, paired call targets, and vtable slots. Changed bodies were aligned
between anchors; conflicting operand pairs were checked against neighboring
references rather than resolved by voting. Data interiors were translated only
where the surrounding mapped references had the same displacement. The source
claims, generated initializer identities, MASM claims, function/data censuses,
and reviewed relocation referents all use 1.1 addresses. The runtime DNA census
was rerun against 1.1. Old scores were discarded and remeasured in strict mode.

The added function at RVA `0x072e57` is `ShutdownComError`, corroborated by
HoMM2 Buka 2.1's `SOURCE/comwin.cpp`. It sits between `init_anchor` and
`com_init`. It is not part of the preceding function's contribution.

For another comparison, the read-only discovery command is:

```sh
homm1 sema fid --old /path/to/old.exe --new /path/to/new.exe \
  --census /path/to/old/config/retail/functions.tsv --out build/fid.json
```

The census must describe the **old** image. Each result includes a fingerprint,
candidates, and its order bracket. Only relocation fields and decoded relative
branch operands are masked; a non-address immediate remains significant.
Fingerprints are candidate identities, not strict-match evidence. Referents and
branch destinations still require inspection. Nonmonotonic unique anchors stop
the command. No source or census is automatically rewritten.

## Source changes

- Chat in combat and network waiting moves from F1 to F2.
- Town entrance hover accepts the secondary trigger on adjacent cells.
- Loading a remote turn and starting a local human turn refresh the hover.
- Identify Hero clears when changing players, rather than once per day.
- New-game human seats inherit the first human's handicap when unset.
- Erasing an object clears its animation flag.
- Combat initialization flushes input and resets the pointer after music starts.
- Serial failures call `ShutdownComError`, which names the Win32 error,
  supplies connection suggestions, and invokes the existing shutdown path.
- The loading string and About dialog say 1.1.

## Validation and remaining work

`homm1 build` runs strict data comparison without unprovisioned identities.
`homm1 link` produces a candidate with no unresolved externals or duplicate
definitions, without `/FORCE`; the resource payloads match 1.1. The generated
README block is the score authority. No game runtime session was performed.

The remaining differences in the newly reconstructed serial routines and
`NewGame` include local placement, register choices and instruction scheduling.
Their calls and intended behavior have been checked against retail, but they
are not claimed byte-exact. Other inherited matching work remains visible in
the normal inventory.

Full `homm1 build verify` still reports the parent's existing failures in
`board`, `casts`, `compiler-artifacts`, and `dead-code`. A control run of
`homm1 verify check --no-readme` on the unchanged parent confirmed the same
findings. The floors and rules have not been relaxed. In particular, this fork
does not resolve the inherited cast recursion findings or CPU-speed assembly
policy finding.

Matching comments describing donor or February retail observations remain
historical evidence. For executable addresses use the current annotations,
retail tables and `homm1 sema`; translate old observations through the migration
table where needed.
