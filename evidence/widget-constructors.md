# Widget default constructors and virtual referents

The seven resource-record default constructors were anonymous in the February 1996 retail image. At RVAs `0x79780` (border), `0x7a9f0` (iconWidget), `0x7add0` (textWidget), `0x7cfe0` (backdropWidget), `0x7e100` (textEntryWidget), `0x7ee20` (dimmerWidget), and `0x7eef0` (button), retail code calls the known base default constructor (`widget` at `0x7f670`, or `textWidget` at `0x7add0`), writes its own vtable, and initializes the fields shown by the stores. Buka 2.1 `BASE/{BORDER,ICONWDGT,TEXTWDGT,BUTTON,DIMMER,Textntry}.cpp` corroborates the source-level constructor family; retail store order determines the VC4 spelling here. Each claimed constructor compares at 100% with code matching active and data matching disabled.

The constructor vtable relocations identify the class tables in retail `.rdata`. The three entries below are in slot order: `Draw`, deleting destructor, `Main`. Each listed destructor reads the scalar-delete flag and returns with `ret 4`; its source is the class destructor, whose body is inlined into this wrapper in retail. These table entries establish identity; only separately annotated source bodies are match claims.

`dimmerWidget`'s destructor is already defined inline in its header, so no new declared-only alias needed an identity row. No virtual body is claimed by this note. Retail `.rdata` relocation targets were read through the pinned PE image; `homm1 sema disasm` independently confirms each constructor's vtable store and zero/init stores.

Fourteen of these virtual targets fell inside overly broad anonymous census rows. `config/retail/functions.tsv` now records their actual entry RVAs so the identity manifest can bind them without pretending that the neighboring code is one function.

`dimmerWidget::Draw` at `0x7eee0` is a five-byte tail jump to `widget::Dim` at `0x7f930`, matching Buka 2.1's one-call body. The latter was another interior entry hidden inside the broad `0x7f710` census row. Its retail code adds the owner window coordinates to the widget coordinates, then passes the manager screen, position, width, and height to `DimBitmapArea` at `0x7c986`. The source body in the existing WIDGET unit and its Draw caller each compare at 100%; the previously mapped WIDGET methods were not changed.

The backdrop and dimmer `Main` entries at `0x7d0d0` and `0x7eed0` each push their message reference, call the same retail target at `0x7f710`, and return with `ret 4`. Buka 2.1 identifies that target as `widget::Main`. Both delegating wrappers compare at 100%. The larger base handler remains an unclaimed referent and a candidate-link unresolved definition.

`backdropWidget::Draw` at `0x7d0e0` calls the reviewed `heroWindowManager::UpdateScreenRegion` target at `0x744b0` with the owner's position added to the widget's position, plus width and height. The constructor-proven table slot, retail member offsets and call arguments identify this body directly; it compares at 100%.

`textWidget::SetText` at `0x7b220` corresponds to Buka 2.1 `BASE/TEXTWDGT.cpp`: text and text-entry kinds own copied storage, grow it by five bytes when the unsigned-word new length exceeds current length, and copy the string; other kinds retain the supplied pointer. Retail and candidate both have the same length, two allocator calls and three branches. The initial 96.0526% register residue closes to 100% with the named owner widget-kind domain and corrected ABI headers in the intended source. Earlier correspondence analysis reversed objdiff's candidate/base and retail/target directory labels; there is no delinker finding here.

The `Main` handlers at `0x79920`, `0x7aba0`, `0x7aff0`, `0x7e360`, `0x7f050` and the base `0x7f710` explicitly return through AX (`xor ax,ax`, `mov ax,1` or `mov ax,2`), with `ret 4`. The family virtual return ABI is therefore `short`, including inherited declarations, rather than the donor-derived `int`. The two authored delegation wrappers change signatures accordingly; their machine code remains exact.

The six authored virtual destructor declarations are explicitly inline, corroborated by Buka's `H2_RETAIL_INLINE` destructors and retail's expanded resource-disposal work inside each scalar deleting wrapper. This closes the previous 51–87% wrapper call-set discrepancies to 100% for all six. The `textEntryWidget` wrapper calls the ordinary `textWidget` destructor at `0x7afc0`; its decoded sequence disposes the font, frees text, and calls the widget destructor, without the scalar-delete flag. It is admitted only as a function identity because the inline definition's separate body is not emitted by the current candidate TU. No address-taking dummy reference was added to force emission.

A real-TU owner-header placement test for that destructor expanded its body inside the text-entry deleting wrapper, lowering its current match to 46.39% and still emitting no standalone ordinary destructor. The test was restored; it does not support the current retail placement.

`textEntryWidget::SetupDisplayString` at `0x7ec90` corresponds to Buka 2.1's helper of the same name. HoMM1 always inserts an underscore cursor and has no donor blink timer. It copies the prefix with `strncpy` at `0x81e80`, appends the remainder, and adjusts the display offset using `font::LineWidth` at `0x7b9c0` and the widget width. Retail reserves 0x130 bytes: a 300-byte display array and an integer changed flag. The body has the same 0x182-byte extent, 134 instructions, four calls, 13 branches, one return, and ordered referents as retail, at 95.0%. The CRT prefix-copy entry is an identity-only referent, excluded from game-function claims.

LineWidth is now reconstructed as a genuine source body at `0x7b9c0`. The pinned FONT profile is `cpp_carcass`: `/Od /Z7 /G5 /Ob1`, confirmed in the emitted compiler command. No optimization flags or source-region optimization pragmas were changed. Retail `0x7b4d0`, `0x7b7a0` and `0x7b9c0` each expand `strlen` into a rep-scan; `#pragma intrinsic(strlen)` restores that library control in FONT. The constructor and destructors remain exact.

PoL 2.0 `BASE/FONT.cpp` preserves the shared original local census for LineWidth: `s`, `q`, `u`, six initialized locals `y,t,r,x,p,w`, and source cursor `v`. Retail retains the six initializers (one dword and five words), uses p/w for index and accumulated width, and directly maps a signed-byte glyph into the frame directory. Recovering those donor-backed locals closes 92.71% to 99.91%; no unexplained local was added for the remaining frame-layout difference. The directory has a 12-byte stride and a signed word width at offset 4, corroborating HoMM1's `IconEntry` layout; Buka's later 13-byte entry includes an extra flags byte absent here. The body has 75 instructions, zero calls, nine branches and one return like retail. The source retains the donor's loop behavior at newline; it is not silently repaired.

`widget::Main` at `0x7f710` corresponds to the Buka event dispatcher, with HoMM1's three widget commands (draw, set flags, clear flags), word flags, special dim request, and mouse-hover rewrite. HoMM1 lacks the donor's later set-coordinate commands and mask branches. `Dim` is expanded at both call sites in retail. An explicit inline declaration under pinned VC4 /Ob1 reproduced the 0x216-byte extent, 188 instructions, seven calls, 18 branches, seven returns and ordered eight referents at 99.42%, but omitted the standalone Dim body required by its separate retail entry. That probe was removed. The retained ordinary declaration preserves standalone Dim and leaves Main at 80.48%; authentic inline definition placement and emission remain open.
